# Классификация вакансий: грейд и направление

По тексту вакансии модель определяет **грейд** (без опыта / 1–3 года / 3–6 лет / более 6 лет)
и **направление** (разработка, аналитика, DS, DevOps, тестирование и т.д.).
Нужно это моему [карьерному боту](https://github.com/zarbondo/ai-career-agent): он собирает вакансии
с hh.ru и подбирает пользователю те, что соответствуют его уровню.

## Главное

- **Разметку никто не делал руками.** Грейд берётся из поля `experience`, направление — из `professional_roles`:
  оба проставляет сам работодатель на hh.ru. Это бесплатные таргеты на десятки тысяч вакансий.
- **Две головы на одном энкодере.** Задачи родственные, поэтому вместо двух моделей одна с общим rubert-tiny2
  и двумя линейными головами. Инференс один вместо двух.
- **Есть бейзлайн.** TF-IDF на словах и символьных n-граммах плюс логрег. Без него цифры трансформера ничего не значат.
- **Кластеризация эмбеддингов** (UMAP + HDBSCAN) показывает группы вакансий, которые не сводятся
  ни к одной роли из справочника hh.ru.
- **ONNX + FastAPI + Docker:** модель уезжает в прод на CPU, torch в контейнере не нужен.

## Данные

Собираются со страницы поиска hh.ru. API (`api.hh.ru`) с мая 2026 отдаёт 403 любому программному
клиенту независимо от IP и User-Agent, поэтому данные беру из HTML-страницы — но вёрстку парсить не нужно:
hh кладёт весь ответ в JSON внутри `<template id="HH-Lux-InitialState">`, там же лежат оба таргета
и справочник ролей.

Запросы идут по парам (роль, опыт): hh отдаёт максимум 2000 вакансий на запрос, а разбивка по опыту
даёт четыре независимых среза и заодно выравнивает редкие грейды. Текст — название плюс требования
и обязанности из сниппета (`enable_snippets=true`).

Поле `tags` я намеренно не беру: там лежит строка вида «Опыт 3-6 лет», то есть сам таргет.
Условия (`cond`) тоже не беру — там зарплата и график, для задачи это шум.

**Собирать нужно с российского IP:** на зарубежные hh.ru отвечает 451, так что из Colab сбор не пройдёт.
Я собираю локально, а обучаю уже в Colab на готовом `data/vacancies.parquet`.

Что делается на этапе подготовки:

- чистка HTML и пробелов;
- выкидываются вакансии короче 40 символов (мусор и заглушки);
- дедупликация по тексту: одна и та же вакансия часто висит сразу в нескольких ролях;
- роли, где меньше 150 вакансий, сливаются в класс «прочее», иначе в тесте окажутся классы из двух примеров;
- сплит стратифицирован по **паре** (грейд, роль): иначе редкие сочетания вроде «сеньор-тестировщик»
  могут целиком уехать в тест.

## Метрики

Главная — **macro-F1**, а не accuracy: классы несбалансированы, и accuracy переоценит модель,
которая просто угадывает самый частый грейд.

Отдельно считаю **попадание в соседний грейд**. Грейды упорядочены, и ошибка «мидл вместо сеньора»
гораздо мягче, чем «без опыта вместо лида». Обычный macro-F1 эту разницу не видит.

## Запуск

```bash
pip install -r requirements.txt

python main.py --smoke     # прогон всего пайплайна на синтетике, ~1 минута, без сети
pytest                     # тесты подготовки данных и метрик

python main.py collect     # собрать вакансии с hh.ru — только с российского IP
python main.py train       # бейзлайн, rubert, кластеризация, экспорт в onnx
```

Полезные флаги: `--no-cluster` и `--no-onnx` пропускают соответствующие шаги,
`--config` указывает другой конфиг. Все гиперпараметры — в `configs/default.yaml`.

Обучение идёт и на CPU, но на GPU (например, в Colab) заметно быстрее — rubert-tiny2 маленький,
хватает бесплатной T4.

## Сервис

```bash
uvicorn api.main:app --port 8000

curl -X POST localhost:8000/predict -H "Content-Type: application/json" \
  -d '{"text": "Ищем Python-разработчика, опыт от 3 лет, микросервисы, PostgreSQL, Docker"}'
```

```json
{
  "grade": {"label": "3–6 лет", "confidence": 0.81},
  "role":  {"label": "Программист, разработчик", "confidence": 0.93},
  "top_roles": [{"label": "Программист, разработчик", "p": 0.93}, ...]

```

В Docker:

```bash
docker build -t vacancy-classifier .
docker run -p 8000:8000 vacancy-classifier
```

В образ кладётся только `model.onnx` и инференс-зависимости, torch туда не едет.

## Ограничения

- Текст берётся из сниппета, а не из полного описания: модель видит 2–3 предложения, а не всю вакансию.
- Таргет — это то, что работодатель написал в поле «опыт». Иногда он не совпадает с реальными требованиями
  в тексте, так что часть ошибок модели — это шум разметки, а не ошибка модели.
- Вакансии собираются за последние 30 дней, по другим периодам и регионам цифры будут другими.
